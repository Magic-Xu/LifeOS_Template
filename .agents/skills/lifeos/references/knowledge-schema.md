# LifeOS 知识状态模型

只记录会改变检索、判断或维护方式的字段，不要求所有文件使用同一套元数据。

## 历史事实

适用于已经发生的事件、决定、经历和结果。最小字段：

```yaml
记录ID:
记录类型: 历史事实
发生时间:
记录时间:
来源: []
置信度:
```

历史事实不会仅因时间经过而失效。后续资料修正它时，并列保留冲突来源，不静默覆盖。

## 当前状态

适用于当前工作、资产、用药、关系状态、偏好总览等会变化的信息。最小字段：

```yaml
记录类型: 当前状态
截至日期:
更新日期:
复核周期天数:
```

- `截至日期` 表示页面覆盖到哪一天，不代表页面内每一项都在当天重新核验。
- `更新日期` 表示最后一次实质性更新，不因只改格式而刷新。
- `复核周期天数` 只用于提示复核，不表示到期后事实自动失效。
- 回答时仍以条目自己的日期、来源和置信度为准。

## 计划

适用于目标、行动方案和有决策节点的持续事项。最小字段：

```yaml
记录类型: 计划
状态: 进行中/暂缓/完成/放弃
截至日期:
更新日期:
下一步:
下次决策点:
来源: []
置信度:
```

不知道下一步或决策点时明确写“尚未明确”，不能替用户补出行动。

## 别名

只在同一对象确有多种稳定称呼时添加 `别名`。别名放在对象的权威页面，不维护重复的全局词典。名称变更时注明现名、原名和确认来源；不要把不同对象仅因同名合并。

## 渐进补齐

- 新记录按对应类型写入。
- 已有记录只有在被再次整理、引用或核验时才补齐必要字段。
- 不为统一格式批量改写日记、原始报告、账单、照片说明或长期保存的原文。
