# LifeOS

把 LifeOS 当作用户拥有的事实源，不把聊天记忆当作唯一依据。

## 开始任务

1. 确定 LifeOS 根目录：
   - 从当前工作目录向上查找；目录同时存在 `AGENTS.md`、`00-收件箱` 和 `99-系统` 时使用它。
   - 否则解析当前 `SKILL.md` 的真实路径；若它位于 `<根目录>/.agents/skills/lifeos`，使用该根目录。
   - 否则使用环境变量 `LIFEOS_ROOT` 指向的有效目录。
   - 最后检查 `$HOME/Documents/LifeOS`。
   - 所有候选都无效时停止并报告，不扫描主目录，也不猜测其他资料库。
2. 后续所有相对路径都从 LifeOS 根目录解析。
3. 完整读取 LifeOS 根目录的 `AGENTS.md`。
4. 若存在 `99-系统/AI上下文/我的概况.md`、`当前目标.md`、`重要偏好与边界.md`，先读取它们。
5. 根据任务只读取必要领域。具体路由见 [references/context-routing.md](references/context-routing.md)。
6. 创建或更新结构化记录时，读取 [references/knowledge-schema.md](references/knowledge-schema.md)，按历史事实、当前状态或计划选择最小字段。
7. 不为“更懂用户”而无差别扫描整个库；资料不足时说明缺口。

## 回答个人问题

1. 检索相关事件、日记、人物或领域总览。
2. 优先使用带日期和来源的材料；检查是否过期或互相冲突。
3. 当前状态超过页面的复核周期，或条目缺少明确截至日期时，说明资料的时间边界；不把“页面最近修改”当成事实已经核验。
4. 输出依次区分：
   - 已知事实
   - 基于记录的判断
   - 可选行动
   - 仍缺少的信息
5. 对关键结论引用仓库内文件链接、记录日期或记录 ID。
6. 健康任务整理时间线、风险信号和就医问题，不替代诊断或自行修改用药。
7. 财务任务核对数据口径和时间范围，不代替用户执行交易。

## 整理收件箱

完整读取 [references/archive-policy.md](references/archive-policy.md)，然后：

1. 只处理 `00-收件箱` 中尚未标记为已整理的材料。
2. 先输出移动、重命名、拆分、链接、总览更新、原文保存级别和源文件处理计划。
3. 在用户授权的范围内修改；已有明确授权不重复确认，未覆盖的源文件处理先确认。
4. 默认只精简归纳，不把收件箱原文长期归档。只有用户明确要求“完整保留”或同义表达时，才保存原文。
5. 不替用户决定完整保存。仅当材料具有不可替代的证据价值或重大纪念价值时，提醒一次并说明理由；没有确认仍按精简归纳处理。
6. 未长期保存的源文件移入 `.trash/待清理-YYYY-MM-DD/`（目录日期为整理日），到期日为整理日后 30 天；`.trash` 不进入 Git 或加密备份。到期文件列入清理计划，永久删除前确认。
7. 已由用户直接写入 `01-日记` 或长期资料目录的内容视为用户主动保存，不适用收件箱的默认精简规则。
8. 同一事实保留一个权威记录，其他目录通过链接引用。
9. 在 `99-系统/AI整理报告` 生成本次变更报告。
10. 更新受影响的索引、总览和 AI 上下文后，运行 `脚本/检查知识库质量.sh`；检查只读，不得自动删除、移动或改写资料。

## 写入规则

- 已经明确长期保存的原始导入、照片、账单、体检报告和日记只读，不覆盖原文。
- 收件箱原文未长期保存时，结构化记录写明自述或导入日期、来源类型、置信度及“原文未长期保存”，不得制造失效链接。
- 新事实写明日期、来源和置信度；AI 推断必须显式标注。
- 人物、健康、财务等总览是派生视图，不得覆盖原始证据。
- 不把密码、令牌、完整证件号码或解密密钥写入仓库。
- 删除、覆盖、对外发送和大范围重分类须有明确授权；已有授权沿用，超出范围先确认。

## 派生视图与检索

- 人物卡、领域总览、经历索引和 AI 上下文是派生视图；原始证据和权威记录仍是事实依据。
- 先按 [references/context-routing.md](references/context-routing.md) 选择入口，再用文件名、别名和正文关键词缩小范围。
- 同一对象确有多个稳定名称时，在权威页面维护 `别名`，不另建重复词典。
- 若存在 `99-系统/检索测试/检索基准.md`，修改路由、索引或检索规则后用它回归；预期入口或证据应出现在前三个候选中。

## 修改后的闭环

获得相应修改确认后：

1. 更新唯一权威记录，不改写明确长期保存的原文。
2. 只更新确实受影响的索引、总览和 AI 上下文。
3. 在当月 `99-系统/AI整理报告/YYYY-MM.md` 追加精简记录，只写最终变更、保存级别、来源处理、冲突和待确认项。
4. 运行 `脚本/检查知识库质量.sh`。错误必须修复；需要用户决定的警告可以保留并明确报告。
5. 系统维护任务同步更新 `99-系统/AI上下文/系统状态.md`，使首页展示最近一次真实检查结果。

## Git 与备份

- 个人目录的明文不得提交 Git；模板、规则、脚本和 Skill 可以提交。
- 只允许根目录的 `LifeOS-*.zip.age` 加密备份进入 Git。
- 生成备份运行 `脚本/生成加密备份.sh`。
- 提交备份前运行 `脚本/检查可提交内容.sh`。
- 恢复时写入新的目标目录，不覆盖当前 LifeOS。

## 完成标准

- 回答可追溯到资料来源。
- 修改有报告，并按用户确认的“精简归纳”或“完整保留”级别处理原文。
- 当前状态和计划具有明确的时间边界；不知道的下一步或状态没有被擅自补全。
- 明确要求完整保存的材料没有丢失或改写；默认精简材料的源文件已进入带到期日的 `.trash`。
- 没有把个人明文或密钥加入 Git。
- 不确定性、冲突和缺失信息已明确指出。
- 知识库质量检查没有未处理的错误；仍存在的警告已说明原因。
