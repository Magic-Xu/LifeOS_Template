# LifeOS

把日记、经历、人物、健康和财务资料留在自己的文件夹里，让 AI 在需要时找到依据、整理变化、帮助回顾和决策。LifeOS 是一套本地 Markdown 知识库模板，推荐用 **Obsidian 记录、Codex 整理**。

日常只维护两个入口：随手材料放 `00-收件箱`，完整日记写 `01-日记`。其余分类、索引和 AI 上下文由你授权 Codex 维护。本仓库包含空目录、通用规则、模板、Skill 和脚本，不包含作者的个人资料。

**先了解数据边界：** 文件保存在本地，不等于 AI 处理完全离线。使用 Codex 或其他云端 AI 时，任务需要的内容可能发送给相应服务；请按自己的隐私要求决定提供什么。Git 默认忽略个人明文，提交钩子再做检查，但它们不能替代提交前审查。

## 第一次使用

以下命令按 macOS + zsh 编写和验证。需要 Git、[ripgrep](https://github.com/BurntSushi/ripgrep)（`rg`）；加密备份另需 [age](https://github.com/FiloSottile/age)、`zip`、`unzip` 和 `shasum`。使用 Homebrew 时可运行：

```bash
brew install git ripgrep age
```

Obsidian 和 Codex 需自行安装。Markdown 文件也可用其他编辑器打开；Windows 原生终端及其他系统尚未验证，不能直接照搬这里的脚本命令。

### 1. 建立自己的资料库

在本仓库页面点击 **Use this template → Create a new repository**，将新仓库设为 **Private**，然后克隆它。这样个人库与公开模板各自维护：

```bash
git clone https://github.com/YOUR_GITHUB_NAME/LifeOS.git
cd LifeOS
```

只想在本地试用，也可以克隆公开模板后立即移除推送地址：

```bash
git clone https://github.com/Magic-Xu/LifeOS_Template.git LifeOS
cd LifeOS
git remote remove origin
```

下载 ZIP 的用户需先在解压后的目录运行 `git init`，再初始化。没有远端也能记录、整理和备份；使用 Git 是为了启用提交检查与规则版本管理。

### 2. 初始化并打开

在自己的 LifeOS 根目录运行：

```bash
./脚本/初始化LifeOS.sh
```

脚本启用提交钩子，生成本地的个人概况、当前目标、偏好、待确认清单、系统状态及领域索引，并填入创建日期；已有文件不会被覆盖。它还尝试将项目 Skill 链接到 `${CODEX_HOME:-$HOME/.codex}/skills/lifeos`，已有同名 Skill 时保留原配置。

如果只在项目内使用 Skill，或有多个 LifeOS，可以跳过全局链接：

```bash
./脚本/初始化LifeOS.sh --skip-global-skill
```

用 Obsidian 打开这个文件夹，设置新笔记位置为 `00-收件箱`、附件位置为 `90-附件`，按需启用核心插件“日记”和“模板”，模板目录选 `99-系统/模板`。社区插件不是必需条件。

在 Codex 中打开同一个个人库。调用 `$lifeos`；若没有显示该 Skill，直接要求读取并执行 `.agents/skills/lifeos/SKILL.md`。优先从当前项目确定资料库，不在其他项目里依靠同名全局 Skill 猜测目标。

### 3. 用一条记录走通流程

在 `00-收件箱/第一次记录.md` 写下今天的一件事。随后告诉 Codex：

```text
使用 $lifeos 整理收件箱。默认精简归纳，先列出归档计划、保存级别和源文件处理方式。
```

确认计划后，Codex 应建立带日期、来源和置信度的记录，更新相关索引，将未长期保存的原文移入回收区，写入当月整理报告并运行质量检查。已有明确授权可以直接沿用。

再问一次“我刚才记录了什么，依据在哪里”，确认它能找到权威记录和来源。这就是最小使用闭环。个人概况和目标可以逐步补充，未知项保持未知。

## 平时如何使用

| 想做的事 | 可以对 Codex 说 |
|---|---|
| 整理新资料 | 使用 `$lifeos` 整理收件箱，先说明计划和原文处理方式。 |
| 保留重要原文 | 这份材料请完整保留原文，再提取结构化记录并链接来源。 |
| 回顾经历 | 使用 `$lifeos` 回顾我过去类似选择的结果，区分事实和推断。 |
| 确定当前优先级 | 使用 `$lifeos` 结合当前目标和近期记录，说明哪些状态需要重新确认。 |
| 更新变化 | 我的某项情况变了，请记录变化日期和来源，更新受影响的总览。 |
| 维护系统 | 使用 `$lifeos` 检查知识库，修复错误，列出需要我决定的警告并更新系统状态。 |

完整日记可直接写在 `01-日记/YYYY-MM-DD.md`，无需先填元数据。你主动保存的日记和长期资料不会因为已经提取摘要而被删除。

收件箱默认精简归纳；要保留原文，请明确说“完整保留”。精简后的源文件进入 `.trash/待清理-YYYY-MM-DD/`，**目录日期是整理日，30 天后才到期**。回收区不进入 Git 或加密备份，到期也须经你确认才永久删除。旧库若用到期日命名过批次，升级时应按原整理报告核对，勿直接改名或清理。

## 记录为什么能持续使用

- **历史事实**记录发生时间、记录时间、来源和置信度；后续有冲突时并列保留依据。
- **当前状态**记录截至日期、更新日期和复核周期。页面刚被编辑不代表全部事实刚被核验，过期只提示复核。
- **计划**记录状态、下一步和下次决策点。未知就写“尚未明确”，不让 AI 替你补出承诺。

同一事实只保留一处权威记录，人物卡、总览、索引和 AI 上下文通过链接引用。健康记录用于时间线与就医准备，财务记录先核对口径；AI 不代替诊断、用药决定或交易。

详见 [字段规范](.agents/skills/lifeos/references/knowledge-schema.md)、[读取路由](.agents/skills/lifeos/references/context-routing.md) 和 [归档规则](.agents/skills/lifeos/references/archive-policy.md)。

## 检查与日常维护

整理、规则升级或重要修改后，在个人库运行：

```bash
./脚本/检查知识库质量.sh
```

它只读检查 Wiki 链接、重复记录 ID、来源与置信度字段、状态复核时间、未结束计划的决策点、无入链记录、回收批次和备份状态。检查有错误时先修复；警告需要结合实际判断，不自动移动或删除资料。

空白库提示“没有备份、没有检索基准、当月没有报告”是正常的建设提醒。完成整理后，让 Codex 在 `99-系统/AI整理报告/YYYY-MM.md` 追加最终变化，并将真实检查结果更新到 `99-系统/AI上下文/系统状态.md`；初始化日期不是检查通过的证据。

资料积累后，在 `99-系统/检索测试/检索基准.md` 保存几个经常问的真实问题，逐步增加：

```markdown
| 编号 | 问题 | 预期入口 | 权威证据 |
|---|---|---|---|
| RET-001 | 一个真实问题 | 已有页面的 Wiki 链接 | 对应证据的 Wiki 链接 |
```

修改路由或索引后，用这些问题回归，确认预期入口或证据能进入前三个候选。脚本只检查用例数量与链接，不会替 AI 验证检索排名。示例行应替换成自己的真实问题和已有链接。

## 加密备份与恢复

在个人库执行以下命令，私钥放在库外，并另存一份到安全位置。已有密钥或公钥配置时初始化会停止，避免意外更换加密身份。

```bash
./脚本/初始化加密.sh "$HOME/Documents/LifeOS-解密密钥.txt"
./脚本/生成加密备份.sh
```

用脚本实际输出的文件名替换下面的 `LifeOS-YYYYMMDD-HHMMSS.zip.age`：

```bash
./脚本/验证备份.sh "LifeOS-YYYYMMDD-HHMMSS.zip.age" "$HOME/Documents/LifeOS-解密密钥.txt"
./脚本/恢复加密备份.sh "LifeOS-YYYYMMDD-HHMMSS.zip.age" "$HOME/Documents/LifeOS-解密密钥.txt" "$HOME/Documents/LifeOS-恢复检查"
```

恢复目标必须是新的或空目录，内容位于其中的原库同名子目录。先验证备份，再恢复并抽查记录和附件；恢复结果不含 `.git`，若重新作为工作库使用，先 `git init` 再运行初始化脚本。没有私钥无法解密。

备份包含个人 Markdown 和附件，排除 `.git`、`.trash`、`.template-backups` 和既有备份。加密文件与其 `.sha256` 校验文件可以提交到**自己的私人仓库**：

```bash
./脚本/检查可提交内容.sh
git add LifeOS-*.zip.age LifeOS-*.zip.age.sha256
./脚本/检查可提交内容.sh --staged
git commit -m "backup: encrypted LifeOS snapshot"
git push
```

仅本地使用时不必执行 Git 提交或推送。脚本在备份达到 80 MiB 时提醒，超过 95 MiB 时阻止 Git 提交；届时将加密文件保存到合适的独立存储，并验证恢复。详见 [备份与恢复](99-系统/工作流/备份与恢复.md)。

## 如何迭代自己的库

个人事实和偏好写在个人目录或 `99-系统/AI上下文`；通用行为规则维护在 `AGENTS.md`、项目 Skill、模板和脚本。优先修改一个权威位置，再同步受影响的说明，避免每个文件重复一套规则。

建议的节奏是：遇到真实问题 → 做最小修改 → 用实际问题或临时测试库验证 → 运行质量检查 → 记录最终变化。只更新受影响的索引与总览，不为统一格式批量改写原始资料。

提交规则或脚本前，检查 `git diff` 和暂存区，再运行：

```bash
./脚本/检查可提交内容.sh
./脚本/检查可提交内容.sh --staged
```

`.gitignore` 与提交钩子使用路径白名单，并检查常见私钥、令牌、个人标识和备份校验。但已经跟踪的文件不会因 `.gitignore` 自动退出 Git，通用文档里也可能混入隐私；不要用强制添加或跳过钩子来消除报错。首次启用或升级后尤其要核对 Git 可见内容。

## 如何接收模板更新

在个人库之外保留一份干净的公开模板副本，只在该副本里拉取更新：

```bash
git clone https://github.com/Magic-Xu/LifeOS_Template.git LifeOS_Template
cd LifeOS_Template
# 已有副本时，从这里开始
git pull --ff-only
./脚本/同步到个人库.sh "/path/to/your/LifeOS" --check
```

先查看列出的文件差异。同步会替换清单中的通用文件，包括 `AGENTS.md`、README、Skill 和脚本；如果你定制过它们，应先保存差异、决定哪些规则继续保留。个人资料重要变更后也应先做一次加密备份。

确定更新后执行：

```bash
./脚本/同步到个人库.sh "/path/to/your/LifeOS" --apply
cd "/path/to/your/LifeOS"
./脚本/初始化LifeOS.sh --skip-global-skill
./脚本/检查知识库质量.sh
./脚本/检查可提交内容.sh
```

同步只复制 [精确文件清单](99-系统/配置/模板同步清单.txt) 中的通用文件。被覆盖的旧文件先保存到目标库 `.template-backups/时间戳/`；目标独有文件保留，个人资料、AI 上下文、整理报告和 `age-recipient.txt` 不会被同步。符号链接或越界路径会阻止执行。

更新后检查个人库的 `git diff`，合并需要保留的定制规则，完成质量与检索回归，再提交通用文件。要撤回某项更新，可从该次 `.template-backups` 取回对应文件，复查后再覆盖；它是本地的升级副本，不属于长期加密备份。

## 如何把个人实践贡献回模板

只提炼在空白库中也适用的规则、模板和脚本改进，在独立模板副本中编辑并提 PR。不要把整个个人库反向复制到公开仓库，也不要上传加密备份、公钥、整理报告、日志或截图里的个人信息。

提交前用临时库验证初始化、重复初始化、升级后的个人资料与公钥不变，以及加密备份的验证和恢复。确认 `.gitignore`、提交检查和同步清单一致，再检查所有待公开差异。新增模板应是空白字段或明确虚构的示例，真实经历不能靠只改姓名完成脱敏。
